# 示例插件

这七个插件编译在 Rome 里，**不会自动装上**。第一次打开 Rome 应该是一个空的应用，
而不是一个已经在替读者抓七个网站的订阅器。它们在「安装插件」里作为一份菜单出现，
点一个就写一份副本到数据目录，之后可以打开读源码。

它们同时是文档。`runtime/README.md` 讲的是运行时的接口，这里讲的是**每种形状长什么样**，
以及为什么值得这么写。

## 抓取型

从别的地方读回条目。五个，按复杂度排：

| 插件 | 教什么 |
| --- | --- |
| `lobsters.js` | 最小的正确形状：一次请求，一个数组，一次映射 |
| `hacker-news.js` | 最简可用形状，外加「用 JSON API 而不是抓 HTML」 |
| `bing-wallpaper.js` | pictures 类型：`image` 必须是绝对 URL |
| `bluesky.js` | 社交时间线，游标来自对方 API，无需登录 |
| `bilibili-popular.js` | 分页游标：每次刷新接着上次的页读，而不是重读第一页 |

## 计算型

条目不是从页面上读下来的，是**拼出来的**。两个：

| 插件 | 教什么 |
| --- | --- |
| `aggregate.js` | 合并两个来源、去重、按热度排序 |
| `digest.js` | 按「站内名次」排序，而不是按原始分数 |

这两个是「为什么非得跑 JavaScript」的答案。抓取型插件说到底只是一个写起来更麻烦的
RSS 阅读器；计算型插件能产出一个 RSS 源和 RSSHub 路由都产不出的东西 —— 条目流是被
组装出来的，不是被读出来的。

`digest.js` 是这个论点的完整版：`aggregate.js` 把分数直接相加，这悄悄假设了 Hacker
News 的 300 分和 Lobsters 的 30 分是同一个单位。它们不是。所以 `digest.js` 改成按
每个来源内部的名次排序，让每个来源都贡献自己的头部，任何一个站都淹没不了整个信息流。

## 一些共同的约定

- **网络只有一条路。** 宿主在加载插件之前把 `XMLHttpRequest`、`WebSocket`、
  `TCPSocket` 这些全删了，并把全局 `fetch` 覆盖成自己那份 —— 所以 `ctx.fetch` 和
  全局 `fetch` 其实是**同一个函数**。示例一律写 `ctx.fetch`，不是因为全局的有问题，
  而是因为它把「这条请求走的是宿主」写在脸上了。走宿主才有 cookie jar、重定向、
  代理，也才会出现在插件的「访问过哪些域名」里。
- **`apiVersion: '1'`。** 宿主会拒绝其它版本。`tests/bundled.rs` 会在编译期之外盯着
  这件事，顺带盯着每个插件的 id 和它的文件名一致。
- **id 由插件自己定，前缀是 `rome.`**，之后的去重靠它。id 变了就是另一条条目。
- **没有 DOM。** 运行时有 `fetch`，但没有 `document`。想读 HTML 就得自己解析字符串，
  所以站点有 JSON API 的时候优先用 JSON API —— 这也是这些示例都尽量用 JSON 的原因。
