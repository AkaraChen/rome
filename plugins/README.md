# 内置插件

这里的插件全部编译在 Rome 里，**不会自动装上**。第一次打开 Rome 应该是一个空的
应用，而不是一个已经在替读者抓几百个网站的订阅器。它们在「插件市场」里作为一份
菜单出现，点一个就写一份副本到数据目录，之后可以打开读源码。

`runtime/README.md` 讲的是运行时的接口。这里讲的是这批插件**从哪来**、**移植时
改了什么**，以及为什么值得这么写。

## 来源

| 来源 | 上游许可证 | 上游规模 |
| --- | --- | --- |
| [RSSHub](https://github.com/DIYgod/RSSHub) `lib/routes/**` | AGPL-3.0 | 1976 个命名空间、3945 条路由 |
| [OpenCLI](https://opencli.info/) `clis/**` | Apache-2.0 | 公开型适配器 |

每个文件的第一行写着它的上游路径，例如：

```js
// Ported from RSSHub lib/routes/zhihu/hot.ts (AGPL-3.0).
```

这一行是给**站点改版**那天用的：选择器不匹配时，第一件要做的事是打开上游那个
文件，看它现在怎么取数据。它也是上游许可证在这棵树里的落点。

移植不是翻译。上游是 TypeScript 服务端代码，这里是一段跑在 txiki.js 里、只能
通过 `ctx` 说话的自包含 ES 模块：

- **没有 DOM。** 运行时有 `fetch`，没有 `document`。站点有 JSON API 就用 JSON
  API；只有 HTML 可读时，就在文件里手写字符串扫描与实体解码。
- **没有依赖。** 不能用 `cheerio`、`got`、`dayjs`。要用到什么（签名、MD5、
  RFC 2822 日期、GBK 之外的字符集）就在文件里实现。
- **没有配置。** 上游从环境变量里读的 token、cookie、代理，这里一律不读。
  需要凭据的路由没有移植 —— 一个装好就报错的插件不如没有。
- **参数变成 `meta.params`。** 上游 `route.parameters` 里的每一个键，在这里都是
  一个表单字段，键名保持一致（`ctx.params['year-from']` 这种带横杠的键也照抄），
  默认值和选项值同样保留。参数为空时抛一句中文错误，而不是发一个注定失败的请求。
- **条目 id 用站点自己的标识。** `zhihu:hot:12345` 而不是数组下标 —— id 变了
  就是另一条条目。
- **空结果算错误。** 上游返回 0 条通常意味着接口变了；静默返回空数组会让读者
  以为「今天没有新闻」。

## 没移植的部分

上游能跑但这里跑不了的，一般是三类：

- **需要浏览器**（`requirePuppeteer`、`antiCrawler`）：运行时不驱动页面。
- **需要登录或密钥**（cookie、`requireConfig`）：宿主不替插件保管账号。
- **依赖 DOM 遍历的复杂页面**：能靠字符串扫描稳定读下来的才移植。

还有一类是**上游已经坏了**的：接口 401、Cloudflare 拦截、站点改版后没有等价
数据源。这些路由跳过，不假装它们还能用。

## 重新生成表

`src/bundled/generated.rs` 是从这些文件的 manifest 生成的，市场卡片画的是它。
加了插件、改了名字或图标之后：

```
just plugins
```

`just plugins-check` 只校验、不重写，适合改一个文件之后先看看有没有写错。
`tests/bundled.rs` 会读同一批 `include_str!`，把表里的四个字段和 manifest 对齐。

## 写自己的插件

看 `runtime/README.md` 的接口表，然后挑一个结构最接近的现成插件改。市场里搜
站点名就能找到它；每个文件顶部的注释解释了它对那个站点做了什么。
